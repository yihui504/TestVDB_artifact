### Cognitive Blindspots

#### BS-01: Parameter Type Coercion Trust
  Developer team assumes REST API framework/serde validates complex nested structures like filter conditions, but validation gaps allow null/object/array type mismatches through silently
  Manifestation: filter.should=null, filter.must_not=object, query=null, vectors={} all accepted with 200 OK but produce undefined behavior
  Attacks: type_confusion_attack, missing_parameter_attack, boundary_value_attack

#### BS-02: Error Message Negligence
  Team prioritizes functional correctness over diagnostic quality - generic 'internal error' messages considered acceptable for edge cases
  Manifestation: Dimension-mismatched vectors silently discarded or return 'Internal Error' instead of 'Vector dimension mismatch'
  Attacks: error_quality_evaluation, diagnostics_gap_analysis

#### BS-03: Concurrency State Blindness
  Team underestimates data consistency impact of concurrent operations during resharding, WAL replay, and distributed scenarios
  Manifestation: WAL replay resurrects deleted points, resharding causes replica count inconsistencies, concurrent updates corrupt state
  Attacks: state_consistency_attack, race_condition_exploration, concurrent_operation_sequence

### By-Design Behaviors (Avoid)

  - HNSW approximation may return duplicate points across offset-based pagination: Issue #9523 - maintainer confirmed this is a known limitation of HNSW approximate search, not a defect

  - jemalloc crashes with 'Unsupported system page size' on ARM64/aarch64: External jemalloc dependency limitation - maintainer acknowledged but deprioritized as infrastructure constraint

  - Snapshot creation timeout/ReadTimeout on large collections: May be resource exhaustion vs defect - check if collection is truly large or if snapshot process is stuck

  - Idempotent DELETE returns 200 even if point doesn't exist: RESTful idempotent delete design - 200 OK is correct response for successful idempotent operation

  - wait=false operations succeed but errors are not logged: Issue #4925 - acknowledged limitation of async operations - low priority enhancement request

  - filter=null in query/search is treated as no-filter: May be intentional API design (null means no filter) vs validation bug - check API specification

  - with_payload parameter defaults to false: Documented default behavior - API specification defines with_payload=false as default

  - Distance enum uses 'Euclid' not 'Euclidean': API design choice - 'Euclid' is the official enum name per specification

  - HNSW search with high ef/limit may return non-deterministic tie-breaking results: Approximate search non-determinism is documented HNSW characteristic

  - Error message field names like 'status', 'time', 'error' are not part of contract: Error message structure is implementation detail, not guaranteed API contract
