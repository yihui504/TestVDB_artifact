# Issue Draft: filter.has_id Returns False Positives

**Candidate ID**: vein_has_id_edge_cases_1
**Novelty Grade**: NOVEL
**Defect Type**: Type4_StateLogicViolation
**Severity**: Low

## Description

The `filter.has_id` condition incorrectly reports existence for non-existent point IDs. When searching or filtering points using `has_id` with IDs that do not exist in the collection, the system returns results indicating these points exist, creating false positives.

## Evidence

- **Endpoint**: `POST /points/search`
- **Parameter**: `filter.has_id`
- **Expected Behavior**: Should only match points that actually exist in the collection
- **Actual Behavior**: Returns matches for non-existent IDs

## Steps to Reproduce

1. Create a collection (e.g., `test_collection`)
2. Add a few points with known IDs (e.g., `[1, 2, 3]`)
3. Execute a search query with `filter.has_id=[999, 1000]` (non-existent IDs)
4. Observe that results incorrectly indicate matches

## Impact

- Applications using `has_id` for existence checks will receive incorrect results
- May lead to data integrity issues in downstream logic
- Violates the documented contract of the filtering API

## Environment

- Qdrant Version: v1.18.2
- API: REST
