# TITLE: `count` `exact=false` on compound filter under-counts 20-60% when conditions touch the same field (independence assumption)

## Current Behavior

`POST /collections/{c}/points/count` with `exact=false` on a **compound** filter (`must` + `must_not`, or multi-`must`) under-counts by 20–60% whenever the combined conditions reference the **same field** (mutually-exclusive values). `exact=true` is correct; the single-condition form is exact-correct on both paths (so the bug is the *combination*, not the leaf estimator).

Not the `total/2` fallback: the error is a percentage, stable across collection sizes (200/500/1000/10000).

The Qdrant OpenAPI specification ([v1.18.3 `openapi.json`](https://github.com/qdrant/qdrant/blob/v1.18.3/docs/redoc/v1.8.x/openapi.json)) defines `exact` as:

> "If `true`, count exact number of points. If `false`, count approximate number of points faster. **Approximate count might be unreliable during the indexing process.**"

The -20% to -60% error occurs at **steady state** (after indexing completes), outside this documented caveat.

## Steps to Reproduce

```python
import json, urllib.request, random, time

BASE = "http://127.0.0.1:6333"

def http(method, path, body=None):
    data = json.dumps(body).encode() if body is not None else None
    req = urllib.request.Request(BASE + path, data=data, method=method)
    if body:
        req.add_header("Content-Type", "application/json")
    with urllib.request.urlopen(req, timeout=20) as resp:
        return resp.status, json.loads(resp.read().decode())

http("DELETE", "/collections/c")
http("PUT", "/collections/c", {
    "vectors": {"size": 2, "distance": "Cosine"},
    "optimizer_config": {"indexing_threshold": 1}
})
random.seed(42)
kws = ["red", "blue", "green", "yellow"]
pts = [{"id": i+1, "vector": [1, 0],
        "payload": {"kw": random.choice(kws), "cat": random.choice(["x", "y"])}} for i in range(500)]
http("PUT", "/collections/c/points?wait=true", {"points": pts})
http("PUT", "/collections/c/index", {"field_name": "kw", "field_schema": "keyword"})
http("PUT", "/collections/c/index", {"field_name": "cat", "field_schema": "keyword"})
time.sleep(3)

def count(flt, exact):
    _, r = http("POST", "/collections/c/points/count", {"exact": exact, "filter": flt})
    return r["result"]["count"]

# Single condition (control) — both paths agree:
print("single:", count({"must":[{"key":"kw","match":{"value":"red"}}]}, True),
      count({"must":[{"key":"kw","match":{"value":"red"}}]}, False))   # 130, 130 (OK)

# Same-field compound (true = red, since red excludes blue):
flt = {"must":[{"key":"kw","match":{"value":"red"}}],
       "must_not":[{"key":"kw","match":{"value":"blue"}}]}
print("same-field:", count(flt, True), count(flt, False))  # 130, ~100 (-23%)

# Cross-field compound (independent fields):
flt = {"must":[{"key":"kw","match":{"value":"red"}},
               {"key":"cat","match":{"value":"x"}}]}
print("cross-field:", count(flt, True), count(flt, False))  # 73, ~62 (-14%)
```

**Output:**
```
single: 130 130       (exact=true, exact=false — both correct)
same-field: 130 100   (-23% under-count)
cross-field: 73 62    (-14% under-count)
```

## Expected Behavior

For `must(red) AND must_not(blue)` on the **same** `kw` field, the result set is exactly `red` (red excludes blue), so the count should equal the single-condition count. The estimator should not assume independence across conditions on the same field.

## Possible Solution

For compound filters where conditions reference the same field, use the single-condition count directly (since mutually-exclusive conditions on one field are equivalent to a single condition). Reserve independence assumptions for genuinely cross-field compounds.

## Context (Environment)

- Qdrant v1.18.3 (commit `db8fa43f`)
- Official Docker image (`qdrant/qdrant:v1.18.3`)
- Single node, default configuration
- Reproduced on 4 collection sizes (200/500/1000/10000) with consistent error percentages

## Detailed Description

The cardinality estimator appears to use an independence assumption when combining conditions: it estimates `P(A AND B) ≈ P(A) × P(B)`. For mutually-exclusive conditions on the same field (e.g., `kw=red AND kw≠blue`), this formula gives `P(red) × P(¬blue) ≈ P(red) × 0.75`, which under-counts by ~25%. The formula is correct for genuinely independent cross-field conditions but wrong for same-field conditions.

**Not a duplicate:** Not the `total/2` fallback (stable percentage, not half collection size).

## Possible Implementation

Detect when compound conditions reference the same field and route through the single-condition cardinality path instead of the independence-assumption combiner.
