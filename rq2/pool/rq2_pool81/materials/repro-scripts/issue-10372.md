# TITLE: `PUT /collections/{c}/index` accepts `field_schema` as a JSON array and creates an index with misinterpreted configuration


## Current Behavior

The openapi schema declares `field_schema` for `PUT /collections/{c}/index` as an object/string variant. Sending it as a **JSON array** is accepted with HTTP 200, and the created payload index derives its configuration by positional deserialization of the array — a silently wrong configuration persists and is visible in the collection info.

## Steps to Reproduce

Verified on **v1.19.0** (same on v1.18.0).

1. Create a collection:

```bash
curl -X PUT http://127.0.0.1:6333/collections/demo -H 'Content-Type: application/json' \
  -d '{"vectors": {"size": 4, "distance": "Euclid"}}'
```

2. Create a payload index with `field_schema` as a JSON array:

```bash
curl -X PUT http://127.0.0.1:6333/collections/demo/index -H 'Content-Type: application/json' \
  -d '{"field_name": "tag", "field_schema": ["keyword"]}'
# → 200 {"result": {"status": "acknowledged"}, ...}
```

3. Observe the created index in the collection info:

```bash
curl http://127.0.0.1:6333/collections/demo
# → payload_schema shows an index for "tag" derived from the array input
```

The data used to reproduce: any collection; the array-form `field_schema` is the only unusual input.

## Expected Behavior

400/422 — `field_schema` as a JSON array does not match any declared schema variant and should be rejected at parse time.

## Possible Solution

Add a post-deserialization validation rejecting `field_schema` values that are sequences, so the invalid shape produces a diagnostic instead of a created index.

## Context (Environment)

- Versions verified: v1.19.0 and v1.18.0, standalone.
- Impact: the index is created from schema-invalid input; the resulting index configuration is derived positionally from the array rather than matching any documented configuration. The invalid input leaves a persistent artifact (the index) rather than an error.

## Detailed Description

- Same root-cause family as other visit_seq positional-deserialization accepts: serde untagged/seq fallback accepts inputs that match no declared variant shape.
- The accepted array input is not equivalent to any documented `field_schema` form, so the resulting index configuration corresponds to no documented request.

## Possible Implementation

- Add a custom deserializer for `field_schema` that rejects sequences explicitly (with a message naming the expected object/string forms), keeping the accept-set identical to the documented variants.
